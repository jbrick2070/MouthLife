MUST-FIX BEFORE BUILD:

1. [§3 + §2.1 + §4.1] Mouthwash's core resource ("Surge Meter == 100%") has no defined charge source, rate, or scope.
   Defect: §3 gates the tool behind "Surge Meter == 100%" but no charge mechanism exists anywhere in the doc except §4.1 District 1's "freed citizens... toss Mouthwash Surge orbs." Districts 2 and 3 never mention Surge orbs, yet §4.1 District 3's finale requires "Mouthwash Surge" as one of three combined tools to hit 90%+ cleanliness, and §2.1 separately describes "a final Mouthwash Remineralization Surge to seal the district" as a one-time district-ending event. It is unclear whether (a) Mouthwash is a repeatable tactical ability charged by some passive/orb mechanic usable per §3's table, or (b) it is a single consumable triggered once per district as in §2.1/§4.1 — these read as two different identities for the same named tool.
   Fix: Define one canonical charge mechanic (e.g., passive regen over time + orb bonuses) and state explicitly whether "the Surge" in §2.1/§4.1 is the same ability as the repeatable §3 Mouthwash or a distinct finisher state.

2. [§6.3] Cleanliness metric is stated as two different formulas with no stated precedence.
   Defect: §6.3 gives a continuous average formula (`1 - sum(density)/count`) immediately followed by "(or binary cell-clean threshold `density <= 0.10`... standardized across HUD and win checks)." These two formulas will diverge on any grid with a mix of cell densities (e.g., many cells sitting just above 0.10 but well below 1.0 inflate the continuous average while failing the binary count) and the doc claims both are used for "HUD and win checks" without saying which governs the `>= 90%` win condition in §2.1.
   Fix: Pick one formula as canonical for HUD display and win-check (recommend the binary `density <= 0.10` count, since it's the one called "standardized"), and state the other is either removed or used only for a secondary/cosmetic readout.

3. [§1.2 vs §5.1] "Daily Arcade Challenge" is claimed as Phase 1 scope in §5.1 but absent from §1.2's Phase 1 scope list and absent from the §6.3 save schema.
   Defect: §1.2 enumerates Phase 1 deliverables exhaustively (Hub, Level 1, Brush-Along Mode, Local Persistence) with no mention of a daily challenge. §5.1 then states "Daily Missions (Phase 1): ... + 1 Daily Arcade Challenge (e.g., 'Clear Premolar Alley in under 45s')" as if it were already in scope. `MouthLifeSaveV1` (§6.3) has no field to track a daily challenge's state, completion, or reward, and §7's acceptance criteria never test it.
   Fix: Either remove "Daily Arcade Challenge" from §5.1's "(Phase 1)" label (defer it with the rest of §5.1's post-Phase-1 extensions) or add it to §1.2's explicit scope list plus a save-schema field and acceptance test.

4. [§4.2] The Stamina/Gum Comfort meter exists for a player-damage event that nothing in the document causes.
   Defect: §4.2 states "Captain Bristle has a Stamina / Gum Comfort meter only for knockback recovery," but no entity or hazard in §4.2 is described as knocking the player back or damaging them. Mutans Sprites only "hop toward Sugar Shards and leave faint plaque trails" (no stated attack), and Acid Puddles only "slow player movement by 30%" (a direct speed debuff, not a knockback/stamina interaction). As written, the meter has no trigger and no function.
   Fix: Either state what causes player knockback (give Mutans Sprites or another hazard an actual attack) or remove the Stamina/Gum Comfort meter from Phase 1 scope.
