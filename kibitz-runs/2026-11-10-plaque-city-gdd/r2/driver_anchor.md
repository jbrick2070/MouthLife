ROUND 2 ANCHOR REVIEW (Driver: Antigravity UI)
Target: kibitz-runs/2026-11-10-plaque-city-gdd/r2/input.md

VERDICT: yes-with-fixes — Concept and dual-loop rules converged well in R1, but R2 needs explicit TypeScript interfaces/method signatures, a low-end-GPU-friendly analytical shader pipeline instead of heavy PBR/shadow maps, a locked DataTexture UV/filtering contract, and WebGL failure fallbacks.

MUST-FIX BEFORE BUILD:
1. [§6.1, §6.3.1] PBR `MeshStandardMaterial.onBeforeCompile` + shadow maps penalize integrated/budget GPUs (CONFIRMED against r2/input.md + user target-hardware constraint): Evaluating full Cook-Torrance GGX PBR across high-DPI viewports and running shadow maps risks sub-30 FPS on Intel UHD Chromebooks, older iPads, and budget phones. Fix:
   - Replace `MeshStandardMaterial.onBeforeCompile` on the tooth arch with a single-pass **Analytical Toon-Enamel `ShaderMaterial`** (vertex-baked cavity AO + cheap Blinn half-vector wet-enamel specular + Fresnel rim + single bilinear `256x128` `DataTexture` lookup using Valve/Splatoon-style `smoothstep(0.08, 0.14, density)` contour magnification for razor-sharp liquid plaque edges at zero extra VRAM/fill cost; ZERO `EffectComposer` post-processing passes).
   - Expand `QualityTier` to 3 explicit profiles (`low` / `medium` / `ultra`, defaulting to `medium` on desktop and `low` on coarse-pointer/mobile, with one-way hysteresis downgrade if rolling 60-frame avg > `22ms`). Only `ultra` enables a directional shadow map; `medium` and `low` use a single `InstancedMesh` blob-shadow batch.
   - Pre-warm shaders via `renderer.compile(scene, camera)` at startup to prevent Windows ANGLE (D3D11) first-use stutter.
2. [§6.2, §6.3] Missing concrete TypeScript interfaces and method signatures for core simulation modules (CONFIRMED against r2/input.md): `PlaqueGrid.ts`, `LevelLayout.ts`, `ArcadeSim.ts`, and `Collision.ts` lack explicit data shapes for entities (`PlayerState`, `CitizenState`, `MutansState`, `SugarShardState`, `BiofilmBridgeState`, `InterdentalAlley`) and exact function signatures. Fix: Define canonical TypeScript interfaces and public method signatures in §6.3 so an implementor cannot diverge on parameter types or return values.
3. [§6.3.1] `DataTexture` UV orientation and bitflag bilinear interpolation hazard (CONFIRMED against r2/input.md): §6.3.1 packs continuous `density` into `R` and bitmask `flags` into `G` of the same `RGBA` `DataTexture`. If `LinearFilter` is enabled for smooth liquid plaque contours, bilinear filtering will interpolate bitmask integers in `G` (`0x02` blended with `0x08` -> `0x05`, corrupting shader flag checks!), and `flipY` vs world `(x, z)` UV mapping is unspecified. Fix: Store continuous visual channels in `RGBA` designed for safe bilinear interpolation (`R = density`, `G = fluorideSeal (0 or 255)`, `B = marginFissureTint (0 or 255)`, `A = paintableMask (0 or 255)`), lock `u = x / 64.0`, `v = z / 32.0`, `flipY = false`, `LinearFilter`, `ClampToEdgeWrapping`, and keep gameplay bitflags strictly on the CPU `Uint8Array`.
4. [§4.1, §6.2] Ambiguous Floss Pick "zip through open interdental shortcuts" mechanic (CONFIRMED against r2/input.md): §3.1/§4.1 says firing Floss Pick down an alley channel zips Captain Bristle through the shortcut, while §6.2 says `Collision.ts` blocks the player (`radius >= 0.6u`) from `< 1.2u` alleys. Without an explicit state transition, collision will trap Captain Bristle mid-zip inside the `0.9u` alley! Fix: Model each `InterdentalAlley` in `LevelLayout.ts` with explicit `endpointA: Vec2`, `endpointB: Vec2`, `width: number`, and `bridgeId: string | null`. When `PlayerState.zipState` is active (`{ from: Vec2, to: Vec2, progress: 0..1, duration: 0.22s }`), player movement interpolates between `endpointA <-> endpointB` cleanly bypassing wall collision until arrival.

SHOULD-FIX:
1. [§6.2, §6.4] Missing WebGL context creation failure handling (CONFIRMED against r2/input.md): §6.3.2 mentions `webglcontextlost`, but if hardware acceleration is disabled (`new THREE.WebGLRenderer()` throws), the app crashes with an uncaught exception. Fix: Wrap `new THREE.WebGLRenderer({ antialias: tier !== 'low', powerPreference: 'high-performance' })` in `try/catch` (with fallback retry `{ antialias: false, powerPreference: 'default' }`) and render a clean DOM fallback notice if WebGL is completely unavailable.
2. [§6.3.3] `Mirror Sync Code` UTF-8 / `btoa` pitfall and field clamping (CONFIRMED against r2/input.md): Standard browser `btoa()` throws `InvalidCharacterError` on non-ASCII characters if JSON ever contains Unicode. Fix: Specify ASCII-safe JSON serialization (`TextEncoder` -> base64url) + strict schema sanitizer clamping maximum array lengths (`unlockedUpgrades.length <= 32`, `Object.keys(dailySlotsByDate).length <= 45`) to prevent storage-DoS via giant pasted strings.
